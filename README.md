## 📶 Тема 1: Сортировка
### 🎯 Цель
Изучить основные принципы сортировки данных и использование компараторов в C++.

### 📖 Теория
**Магия упорядочивания данных**

Сортировка — это процесс упорядочивания элементов по какому-либо признаку (по возрастанию, убыванию или более сложным правилам).

Представь, что у тебя есть колода карт, и тебе нужно найти все пики. Если карты разбросаны в беспорядке, придется просмотреть каждую. Но если они отсортированы по мастям и старшинству, ты найдешь нужные карты за секунду!

В спортивном программировании сортировка часто является первым шагом к решению задачи. Например, чтобы найти два самых больших числа в массиве, проще всего отсортировать его по убыванию и взять первые два элемента.

В C++ есть встроенная функция **sort()**. Она работает за **O(N log N)**, что очень быстро. Обычно она используется с итераторами: `sort(a.begin(), a.end())` или `sort(a, a + n)`. По умолчанию она сортирует по возрастанию.

Но что если нам нужно отсортировать по убыванию? Или отсортировать пары (например, студентов по баллам, а при равенстве баллов — по имени)? В C++ можно передать третьим аргументом **компаратор** — функцию или лямбда-выражение, которая определяет правило сравнения двух элементов.

Существует также **stable_sort()**. В отличие от обычного sort, он сохраняет относительный порядок равных элементов. Это полезно, когда ты сортируешь объекты по одному параметру, а затем по другому.

Помни: сортировка меняет порядок элементов. Если в задаче важны исходные индексы, лучше создать массив пар (значение, индекс) и сортировать его.

### 💻 Шаблон кода
```cpp
#include <bits/stdc++.h>
using namespace std;

// Функция-компаратор для сортировки по убыванию
bool cmp(int a, int b) {
    return a > b;
}

int main() {
    int n;
    cin >> n;
    vector<int> a(n);
    for(int i = 0; i < n; i++) cin >> a[i];

    // Сортировка по возрастанию (по умолчанию)
    sort(a.begin(), a.end());

    // Сортировка по убыванию с помощью компаратора
    sort(a.begin(), a.end(), cmp);

    // Сортировка по убыванию с помощью лямбда-функции (современный C++)
    sort(a.begin(), a.end(), [](int x, int y) {
        return x > y;
    });

    // Пример с парами
    vector<pair<int, int>> vp = {{3, 1}, {1, 2}, {3, 0}};
    // Сначала по первому элементу, затем по второму
    sort(vp.begin(), vp.end());

    return 0;
}
```

### ✨ Ключевые моменты
- Сортировка упорядочивает данные
- В C++ используется функция sort(), работает за O(N log N)
- Компараторы позволяют задавать любые правила сортировки
- Если нужны исходные индексы, используй массив пар

## 🔍 Тема 2: Бинарный поиск
### 🎯 Цель
Понять принцип бинарного поиска и научиться применять его по ответу.

### 📖 Теория
**Угадай число за пару шагов**

Бинарный (двоичный) поиск — это алгоритм поиска элемента в **отсортированном** массиве.

Представь, что ты ищешь слово в словаре. Ты же не листаешь каждую страницу с самого начала? Скорее всего, ты открываешь словарь посередине. Если нужная буква дальше — ты открываешь середину правой половины. Если раньше — середину левой. Это и есть бинарный поиск!

Главное требование для бинарного поиска — данные должны быть отсортированы (или функция должна быть монотонной). Сложность алгоритма **O(log N)**. Это значит, что среди 1 000 000 элементов мы найдем нужный всего за ~20 шагов!

В C++ есть встроенные функции для бинарного поиска:
**lower_bound** — ищет первый элемент, который больше или равен заданному.
**upper_bound** — ищет первый элемент, который строго больше заданного.

Один из самых мощных методов в олимпиадном программировании — **бинарный поиск по ответу**. Если мы знаем, что ответ лежит в диапазоне от `L` до `R`, и мы можем легко проверить, возможно ли достичь результата `M` (где `M` — середина диапазона), мы можем использовать бинарный поиск, чтобы найти оптимальный ответ. Главное условие: если мы можем достичь `M`, то мы можем достичь и любого худшего результата. Это свойство монотонности.

### 💻 Шаблон кода
```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, target;
    cin >> n >> target;
    vector<int> a(n);
    for(int i = 0; i < n; i++) cin >> a[i];
    
    sort(a.begin(), a.end()); // Обязательно сортируем!

    // 1. Ручной бинарный поиск
    int L = 0, R = n - 1;
    bool found = false;
    while(L <= R) {
        int mid = L + (R - L) / 2; // Избегаем переполнения
        if(a[mid] == target) {
            found = true;
            break;
        }
        if(a[mid] < target) L = mid + 1;
        else R = mid - 1;
    }

    // 2. Использование встроенных функций
    // lower_bound возвращает итератор на первый элемент >= target
    auto it1 = lower_bound(a.begin(), a.end(), target);
    if(it1 != a.end() && *it1 == target) cout << "Found!\n";
    
    // upper_bound возвращает итератор на первый элемент > target
    auto it2 = upper_bound(a.begin(), a.end(), target);
    cout << "Число элементов <= target: " << (it2 - a.begin()) << "\n";

    // 3. Шаблон бинарного поиска по ответу
    /*
    long long l = 0, r = 1e18, ans = 0;
    while(l <= r) {
        long long mid = l + (r - l) / 2;
        if(check(mid)) {
            ans = mid;
            r = mid - 1; // или l = mid + 1, зависит от задачи
        } else {
            l = mid + 1; // или r = mid - 1
        }
    }
    */
    return 0;
}
```

### ✨ Ключевые моменты
- Массив должен быть отсортирован перед бинарным поиском
- Работает за O(log N) — очень быстро
- lower_bound(>=) и upper_bound(>)
- Бинарный поиск по ответу — мощный прием для сложных задач

## ➕ Тема 3: Префиксные суммы
### 🎯 Цель
Научиться быстро вычислять сумму на отрезке массива за O(1).

### 📖 Теория
**Ускоряем сумму на отрезке**

Что делать, если у нас есть большой массив, и нам постоянно задают вопросы: 'А какая сумма элементов с L-го по R-й?'

Если считать циклом каждый раз, мы потратим O(N) времени на один запрос. А если запросов 100 000? Программа будет работать слишком долго! Здесь нас спасают **префиксные суммы**.

Идея проста: давайте заранее посчитаем сумму всех элементов от начала массива до каждого индекса `i` и сохраним это в новый массив `pref`. То есть `pref[i] = a[0] + a[1] + ... + a[i]`.

Как теперь быстро найти сумму от `L` до `R`? Очень легко! Это сумма всех элементов до `R` минус сумма всех элементов до `L-1`. То есть `sum(L, R) = pref[R] - pref[L-1]`. Теперь ответ на запрос занимает **O(1)** времени!

Часто удобно делать массив префиксов на 1 больше размера исходного массива: `pref[0] = 0`, `pref[1] = a[0]`, `pref[2] = a[0] + a[1]` и так далее. При 1-индексации формула становится красивой: `sum(L, R) = pref[R] - pref[L-1]`, и нам не нужно думать о выходе за границы массива при `L=0`.

Этот метод можно обобщить и для **двумерных массивов** (матриц). Двумерная префиксная сумма `pref[i][j]` хранит сумму всех элементов в прямоугольнике от (0,0) до (i,j). Формула включений-исключений для ответа на запрос о сумме в любом прямоугольнике: `S = pref[R][C] - pref[r-1][C] - pref[R][c-1] + pref[r-1][c-1]`.

### 💻 Шаблон кода
```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // Ввод размера массива и количества запросов
    int n, q;
    cin >> n >> q;
    vector<long long> a(n + 1);
    
    // Считываем данные в 1-индексации
    for(int i = 1; i <= n; i++) {
        cin >> a[i];
    }

    // Строим массив префиксных сумм
    vector<long long> pref(n + 1, 0);
    for(int i = 1; i <= n; i++) {
        pref[i] = pref[i - 1] + a[i];
    }

    // Обрабатываем запросы за O(1)
    while(q--) {
        int l, r;
        cin >> l >> r;
        // Сумма на отрезке [l, r]
        long long sum = pref[r] - pref[l - 1];
        cout << sum << "\n";
    }

    return 0;
}
```

### ✨ Ключевые моменты
- Префиксные суммы ускоряют ответы на запросы суммы с O(N) до O(1)
- Формула: pref[i] = pref[i-1] + a[i]
- Сумма на отрезке [L, R] = pref[R] - pref[L-1]
- Удобно использовать 1-индексацию для избежания выхода за пределы массива
- Можно обобщить для 2D массивов (матриц)

## 🤑 Тема 4: Жадные алгоритмы
### 🎯 Цель
Научиться применять локально оптимальные решения.

### 📖 Теория
**Хватай то, что лучше прямо сейчас!**

Жадный алгоритм — это метод, при котором на каждом шагу мы принимаем **локально оптимальное** решение, надеясь, что в итоге оно приведет к **глобальному оптимуму**.

Представь, что тебе нужно набрать сдачу 42 рубля минимальным количеством монет. У тебя есть монеты: 10, 5, 2 и 1 рубль. Как ты поступишь? Ты будешь брать самую крупную монету, пока это возможно. 4 монеты по 10 рублей (осталось 2), и затем 1 монета в 2 рубля. Итого 5 монет. Это и есть жадный подход! Ты не думаешь о будущем, ты берешь то, что кажется лучшим в данный момент.

Однако жадные алгоритмы работают не всегда. Например, если бы монеты были 25, 20 и 1 рубль, а сдача 40. Жадный алгоритм дал бы: 25 + 15 единичек (16 монет). Но правильный ответ: 20 + 20 (2 монеты). Поэтому важно уметь доказывать корректность жадного выбора.

Доказательство часто строится от противного или методом 'exchange argument' (доказательство обменом): мы предполагаем, что оптимальный ответ отличается от нашего жадного выбора, и показываем, что мы можем изменить оптимальный ответ в сторону нашего жадного выбора без ухудшения результата.

Классические паттерны жадных алгоритмов:
- Сортировка: отсортировать объекты по цене, весу, дедлайну и брать лучшие.
- Макро-выбор: всегда брать самое большое/маленькое значение из доступных (часто с использованием `priority_queue` или `set`).
- Задачи на отрезки: например, выбрать максимальное количество непересекающихся отрезков на прямой (надо сортировать по правой границе!).

### 💻 Шаблон кода
```cpp
#include <bits/stdc++.h>
using namespace std;

// Пример: задача о выборе максимального количества непересекающихся отрезков
int main() {
    int n;
    cin >> n;
    vector<pair<int, int>> segments(n);
    
    for(int i = 0; i < n; i++) {
        cin >> segments[i].first >> segments[i].second;
    }

    // Жадный шаг: сортируем отрезки по правому концу (времени завершения)
    sort(segments.begin(), segments.end(), [](pair<int, int>& a, pair<int, int>& b) {
        return a.second < b.second;
    });

    int count = 0;
    int last_end_time = -1;

    // Проходим по отрезкам и берем те, которые не пересекаются с предыдущим выбранным
    for(int i = 0; i < n; i++) {
        if(segments[i].first >= last_end_time) {
            count++;
            last_end_time = segments[i].second;
        }
    }

    cout << count << "\n";
    return 0;
}
```

### ✨ Ключевые моменты
- На каждом шаге принимаем лучшее решение на данный момент
- Жадность не всегда работает, важно уметь обосновать выбор
- Сортировка — лучший друг жадных алгоритмов
- Если жадный подход очевиден, но не работает — возможно, нужно динамическое программирование

## 👆 Тема 5: Два указателя
### 🎯 Цель
Освоить прием "два указателя" для оптимизации алгоритмов.

### 📖 Теория
**Сжимаем алгоритмы как гармошку**

Два указателя (Two Pointers) — это оптимизационный прием, который позволяет уменьшить сложность с O(N^2) до O(N). Идея состоит в том, чтобы использовать две переменные ('указатели') для перебора массива, обычно двигая их в одном направлении или навстречу друг другу.

Существует два основных вида:

1. **Указатели навстречу друг другу (Начинаются с концов).**
Часто используется в отсортированных массивах. Например, найти две суммы элементов, равные заданному X. Мы ставим левый указатель `L` на начало, правый `R` на конец. Если их сумма меньше X — увеличиваем `L`. Если больше — уменьшаем `R`. Если равна — ответ найден!

2. **Указатели в одном направлении (Sliding Window / Скользящее окно).**
Оба указателя `L` и `R` начинают с нуля. Мы двигаем правый `R` вперед, добавляя элементы в 'окно'. Как только условие задачи нарушается (например, сумма в окне превысила предел), мы начинаем двигать левый `L`, 'сбрасывая' элементы, пока окно снова не станет валидным. 

Сложность O(N) достигается за счет того, что каждый указатель двигается только вперед. Несмотря на вложенный цикл `while`, левый и правый указатель за весь алгоритм сделают суммарно не более 2N шагов.

### 💻 Шаблон кода
```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // Пример скользящего окна (Sliding Window)
    // Найти самую длинную подотрезок, сумма элементов которого <= S
    int n;
    long long S;
    cin >> n >> S;
    vector<int> a(n);
    for(int i = 0; i < n; i++) cin >> a[i];

    long long current_sum = 0;
    int L = 0, max_len = 0;

    for(int R = 0; R < n; R++) {
        current_sum += a[R]; // Добавляем элемент в окно

        // Если окно 'переполнено', двигаем L
        while(current_sum > S && L <= R) {
            current_sum -= a[L];
            L++;
        }

        // Обновляем максимальную длину валидного окна
        max_len = max(max_len, R - L + 1);
    }

    cout << max_len << "\n";
    
    // Пример указателей навстречу (Поиск пары чисел с суммой X)
    /*
    sort(a.begin(), a.end());
    int l = 0, r = n - 1;
    while(l < r) {
        if(a[l] + a[r] == X) { cout << "YES"; return 0; }
        if(a[l] + a[r] < X) l++;
        else r--;
    }
    */
    return 0;
}
```

### ✨ Ключевые моменты
- Снижает сложность с O(N^2) до O(N)
- Окно (L, R) двигается только вперед, не возвращаясь назад
- Скользящее окно используется для поиска подотрезков, удовлетворяющих условию
- Указатели навстречу часто требуют предварительной сортировки массива

## 🌀 Тема 6: Рекурсия
### 🎯 Цель
Понять принцип работы функций, вызывающих самих себя, и бэктрекинг.

### 📖 Теория
**Функция, которая вызывает саму себя**

Рекурсия — это когда функция вызывает саму себя внутри себя же. Звучит как магия (или ошибка, которая приведет к бесконечному циклу), но если все сделать правильно, рекурсия становится невероятно мощным инструментом.

Представь себе матрешку. Чтобы добраться до самой маленькой матрешки, нужно открыть большую, потом ту, что внутри нее, и так далее. Открытие каждой новой матрешки — это рекурсивный вызов.

Чтобы рекурсия не была бесконечной, у нее обязательно должен быть **базовый случай** (условие выхода). В примере с матрешкой — это самая маленькая неразборная матрешка.

Каждый вызов функции сохраняется в **стеке вызовов** (call stack) в памяти. Поэтому слишком глубокая рекурсия (глубже ~10000 вызовов) может привести к ошибке Stack Overflow (переполнение стека). Но в большинстве олимпиадных задач этого не происходит.

Рекурсия очень полезна для полного перебора (Brute Force) и **бэктрекинга** (поиск с возвратом). Например, когда нам нужно сгенерировать все возможные перестановки чисел, комбинации скобок или расставить ферзей на шахматной доске. В бэктрекинге мы делаем выбор, вызываем рекурсию, а затем 'отменяем' этот выбор, чтобы попробовать другой вариант.

### 💻 Шаблон кода
```cpp
#include <bits/stdc++.h>
using namespace std;

// Пример 1: Вычисление факториала
long long factorial(int n) {
    // Базовый случай
    if (n == 0 || n == 1) return 1;
    // Рекурсивный переход
    return n * factorial(n - 1);
}

// Пример 2: Генерация всех бинарных строк длины n
void generate_binary(int n, string current) {
    // Базовый случай: строка достигла нужной длины
    if (current.length() == n) {
        cout << current << "\n";
        return;
    }
    
    // Рекурсивные вызовы
    generate_binary(n, current + "0");
    generate_binary(n, current + "1");
}

// Пример 3: Бэктрекинг - генерация всех перестановок чисел от 1 до N
int n;
vector<int> perm;
vector<bool> used;

void generate_permutations() {
    if (perm.size() == n) {
        for(int x : perm) cout << x << " ";
        cout << "\n";
        return;
    }
    for(int i = 1; i <= n; i++) {
        if (!used[i]) {
            used[i] = true;      // Делаем выбор
            perm.push_back(i);
            
            generate_permutations(); // Рекурсивный вызов
            
            perm.pop_back();     // Отменяем выбор (backtrack)
            used[i] = false;
        }
    }
}

int main() {
    n = 3;
    used.assign(n + 1, false);
    generate_permutations();
    return 0;
}
```

### ✨ Ключевые моменты
- Рекурсия — вызов функцией самой себя
- Обязательно нужен базовый случай (условие выхода)
- Рекурсия использует стек вызовов, будь осторожен с глубиной
- Бэктрекинг — это рекурсивный перебор с 'откатом' (отменой) действия

## 🧠 Тема 7: Базовое динамическое программирование
### 🎯 Цель
Понять принцип решения задач методом ДП: разбиение на подзадачи.

### 📖 Теория
**Динамическое программирование: разбиваем и властвуем**

Динамическое программирование (ДП) — это способ решения сложных задач путем разбиения их на более простые подзадачи. Главная идея: мы решаем каждую подзадачу только один раз и запоминаем ответ. Если эта подзадача встретится снова, мы просто возьмем готовый ответ из памяти.

ДП опирается на две важные концепции. Первая — **перекрывающиеся подзадачи**. Это значит, что одни и те же подзадачи встречаются снова и снова. Представьте, что вы считаете числа Фибоначчи. Чтобы найти F(5), нужны F(4) и F(3). А для F(4) нужны F(3) и F(2). Как видите, F(3) нужно вычислить несколько раз!

Вторая концепция — **оптимальная подструктура**. Оптимальное решение большой задачи можно составить из оптимальных решений ее подзадач. Если вы ищете самый короткий путь из города А в город В через город Б, этот путь будет состоять из кратчайшего пути от А до Б и кратчайшего пути от Б до В.

Есть два основных подхода к ДП. **Нисходящий (Top-down)**, или мемоизация: мы пишем рекурсивную функцию и сохраняем результаты ее работы в массив. Это естественно и просто пишется, но может занимать больше памяти из-за стека вызовов. **Восходящий (Bottom-up)**, или табуляция: мы сначала решаем самые маленькие подзадачи и записываем ответы в массив (или таблицу), а затем используем их для решения более крупных задач, пока не дойдем до исходной.

Классические примеры ДП — это числа Фибоначчи (каждое следующее равно сумме двух предыдущих), задача о рюкзаке (выбрать предметы с максимальной ценностью, чтобы они влезли в рюкзак определенной вместимости), задача о размене монет (выдать сумму минимальным количеством монет) и задача о кузнечике (или лесенке), где нужно найти количество путей добраться до последней ступеньки.

При решении задач на ДП всегда начинайте с определения **состояния** (что именно мы храним в массиве или таблице, например, dp[i] — максимальная выгода на i-м шаге) и вывода **перехода** (как получить dp[i], зная предыдущие значения, например, dp[i] = max(dp[i-1], dp[i-2] + a[i])).

### 💻 Шаблон кода
```cpp
#include <bits/stdc++.h>
using namespace std;

// Пример классической задачи: числа Фибоначчи с мемоизацией
const int MAXN = 100005;
int memo[MAXN];

int fib(int n) {
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n];
    // Запоминаем ответ перед возвратом
    return memo[n] = fib(n - 1) + fib(n - 2);
}

int main() {
    int n;
    cin >> n;
    
    // Top-down (мемоизация)
    memset(memo, -1, sizeof(memo));
    cout << fib(n) << "\n";
    
    // Bottom-up (табуляция)
    vector<int> dp(n + 1);
    dp[0] = 0;
    if (n > 0) dp[1] = 1;
    for (int i = 2; i <= n; i++) {
        dp[i] = dp[i-1] + dp[i-2];
    }
    cout << dp[n] << "\n";
    
    return 0;
}
```

## 🕸️ Тема 8: Графы: BFS и DFS
### 🎯 Цель
Научиться представлять графы в памяти и обходить их.

### 📖 Теория
**Графы: путешествия по вершинам**

Графы — это математическая абстракция, представляющая связи между объектами. Объекты называются **вершинами** (узлами), а связи между ними — **ребрами**. Графы используются для моделирования дорог, социальных сетей, компьютерных сетей и многого другого.

В программировании графы чаще всего представляются в виде **списка смежности** (adjacency list) — массива или вектора, где для каждой вершины хранится список ее соседей. Это очень эффективно по памяти, особенно для разреженных графов (где мало ребер по сравнению с возможным максимумом).

Существует два основных алгоритма обхода графа. Первый — это **поиск в глубину (DFS, Depth-First Search)**. Представьте, что вы исследуете лабиринт. Вы идете по одному пути так далеко, как только можете, пока не упретесь в тупик. Затем вы возвращаетесь (backtrack) до ближайшей развилки и пробуете другой путь. DFS легко реализуется с помощью рекурсии и отлично подходит для поиска связных компонент, проверки графа на двудольность или поиска циклов.

Второй алгоритм — **поиск в ширину (BFS, Breadth-First Search)**. Вместо того, чтобы идти вглубь, мы сначала исследуем всех соседей начальной вершины, затем соседей этих соседей и так далее. Это похоже на расходящиеся круги на воде. BFS реализуется с помощью очереди (queue). Его главная суперсила — он находит **кратчайший путь** (в графах, где все ребра имеют одинаковую длину или вес) от стартовой вершины ко всем остальным.

**Поиск циклов** в неориентированном графе с помощью DFS работает просто: если мы из текущей вершины пытаемся пойти в уже посещенную вершину, и это не та вершина, из которой мы только что пришли — значит, в графе есть цикл. В ориентированном графе нужно различать три состояния вершины (цвета): белая (не посещена), серая (в процессе обработки, т.е. мы в рекурсии), черная (полностью обработана). Цикл есть, если мы из текущей вершины пытаемся пойти в серую.

### 💻 Шаблон кода
```cpp
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 100005;
vector<int> adj[MAXN];
bool visited[MAXN];
int dist[MAXN];

// Поиск в глубину (DFS)
void dfs(int u, int p = -1) {
    visited[u] = true;
    for (int v : adj[u]) {
        if (v != p && !visited[v]) {
            dfs(v, u);
        }
    }
}

// Поиск в ширину (BFS)
void bfs(int start) {
    memset(dist, -1, sizeof(dist));
    queue<int> q;
    q.push(start);
    dist[start] = 0;
    
    while (!q.empty()) {
        int u = q.front();
        q.pop();
        
        for (int v : adj[u]) {
            if (dist[v] == -1) {
                dist[v] = dist[u] + 1;
                q.push(v);
            }
        }
    }
}

int main() {
    int n, m; // n - вершины, m - ребра
    cin >> n >> m;
    for (int i = 0; i < m; i++) {
        int u, v;
        cin >> u >> v;
        adj[u].push_back(v);
        adj[v].push_back(u); // Для неориентированного графа
    }
    
    dfs(1);
    bfs(1);
    
    return 0;
}
```

### ✨ Ключевые моменты
- Используйте список смежности (vector<int> adj[N]) для хранения графа.
- DFS (в глубину) — рекурсия, хорош для связности, циклов, топологической сортировки.
- BFS (в ширину) — очередь, находит кратчайший путь в невзвешенных графах.
- Обязательно храните массив visited, чтобы не зациклиться!

## 🔢 Тема 9: Теория чисел
### 🎯 Цель
Освоить алгоритмы на простые числа и арифметику остатков.

### 📖 Теория
**Магия чисел: НОД, простые числа и остатки**

Теория чисел — это раздел математики, изучающий целые числа и их свойства. В спортивном программировании мы часто сталкиваемся с задачами на делимость, простые числа и модульную арифметику.

Одно из самых важных понятий — **Наибольший общий делитель (НОД, GCD)**. Это самое большое число, на которое делятся без остатка два заданных числа. Алгоритм Евклида позволяет находить НОД очень быстро: НОД(a, b) = НОД(b, a % b). Зная НОД, легко найти **Наименьшее общее кратное (НОК, LCM)**: НОК(a, b) = (a * b) / НОД(a, b).

**Простое число** — это число, большее 1, которое делится только на 1 и на само себя. Чтобы проверить, простое ли число `n`, достаточно проверить делимость на все числа от 2 до `sqrt(n)`. Если делителей нет, число простое. Это работает, потому что делители ходят парами: если `d` делит `n`, то и `n/d` делит `n`. Одно из чисел в паре обязательно меньше или равно корню.

Если нужно найти все простые числа до какого-то большого `N` (например, миллиона), используют **Решето Эратосфена**. Идея гениально проста: выписываем все числа от 2 до `N`. Первое невычеркнутое число (2) — простое. Вычеркиваем все его кратные (4, 6, 8...). Следующее невычеркнутое (3) — тоже простое. Вычеркиваем его кратные и так далее.

**Модульная арифметика**. Часто в задачах просят вывести ответ "по модулю 10^9 + 7". Это делается, чтобы ответы не выходили за границы типов данных (переполнение). Важные правила: `(a + b) % M = (a % M + b % M) % M`, то же самое для умножения и вычитания. При вычитании может получиться отрицательное число, поэтому правильнее писать `(a - b % M + M) % M`. Деление по модулю сложнее и требует вычисления обратного элемента (обычно через Малую теорему Ферма).

Интересный факт: **Гипотеза Гольдбаха** утверждает, что любое четное число больше 2 можно представить в виде суммы двух простых чисел. Это часто помогает в задачах!

### 💻 Шаблон кода
```cpp
#include <bits/stdc++.h>
using namespace std;

// Функция для нахождения НОД (GCD)
// В C++ есть встроенная функция std::gcd(a, b) в <numeric>
long long gcd(long long a, long long b) {
    while (b) {
        a %= b;
        swap(a, b);
    }
    return a;
}

// Функция для нахождения НОК (LCM)
long long lcm(long long a, long long b) {
    return (a / gcd(a, b)) * b;
}

// Проверка на простоту за O(sqrt(n))
bool is_prime(long long n) {
    if (n < 2) return false;
    for (long long i = 2; i * i <= n; i++) {
        if (n % i == 0) return false;
    }
    return true;
}

// Решето Эратосфена за O(N log log N)
vector<bool> sieve(int n) {
    vector<bool> is_prime(n + 1, true);
    is_prime[0] = is_prime[1] = false;
    for (int p = 2; p * p <= n; p++) {
        if (is_prime[p]) {
            for (int i = p * p; i <= n; i += p)
                is_prime[i] = false;
        }
    }
    return is_prime;
}
```

### ✨ Ключевые моменты
- Используйте std::gcd(a, b) для нахождения НОД.
- Проверка на простоту одного числа работает за O(sqrt(N)).
- Для поиска всех простых чисел до N используйте Решето Эратосфена.
- При вычислениях по модулю берите остаток после каждой операции (+, -, *).

## 🌳 Тема 10: Деревья и СНМ (DSU)
### 🎯 Цель
Понять деревья как особый вид графов и изучить структуру СНМ.

### 📖 Теория
**Лесные массивы и объединение множеств**

Дерево в теории графов — это связный неориентированный граф без циклов. Любые две вершины в дереве соединены ровно одним простым путем. Если в дереве `N` вершин, то в нем ровно `N - 1` ребро.

Обычно в дереве выделяют одну особую вершину — **корень** (root). От корня можно спуститься к **детям**, а от детей — к **родителям**. Вершины без детей называются **листьями**. Для обхода деревьев чаще всего используют DFS. Особенность DFS на деревьях в том, что нам не нужен массив `visited`! Достаточно передавать в функцию родителя текущей вершины и не идти обратно в него.

**Система Непересекающихся Множеств (СНМ, или DSU - Disjoint Set Union)** — это невероятно красивая и быстрая структура данных. Она позволяет хранить множество элементов, разбитых на непересекающиеся подмножества, и выполнять две операции: узнать, какому множеству принадлежит элемент (`find`), и объединить два множества (`union`).

Идея СНМ: мы представляем каждое множество в виде дерева, где корень — это "лидер" (или представитель) множества. Изначально каждый элемент — сам себе лидер.
Операция `find(x)` просто поднимается от `x` к родителю, пока не дойдет до корня.
Операция `union(x, y)` находит корни `x` и `y` и делает один корень родителем другого.

Чтобы СНМ работал за почти константное время (O(1)), нужны две оптимизации. Первая — **сжатие путей (path compression)**: во время выполнения `find` мы переподвешиваем все пройденные вершины напрямую к корню. Вторая — **эвристика по рангу/размеру (union by size/rank)**: при объединении мы всегда подвешиваем корень меньшего дерева к корню большего. Вместе эти эвристики делают амортизированную сложность операций равной обратной функции Аккермана, что на практике быстрее, чем любая константа.

### 💻 Шаблон кода
```cpp
#include <bits/stdc++.h>
using namespace std;

// Структура DSU (СНМ) с обеими эвристиками
struct DSU {
    vector<int> parent;
    vector<int> size;

    DSU(int n) {
        parent.resize(n);
        size.resize(n, 1);
        for(int i = 0; i < n; i++) {
            parent[i] = i;
        }
    }

    // Поиск корня (лидера) со сжатием пути
    int find_set(int v) {
        if (v == parent[v])
            return v;
        // Рекурсивный вызов и переподвешивание
        return parent[v] = find_set(parent[v]);
    }

    // Объединение множеств по размеру
    void union_sets(int a, int b) {
        a = find_set(a);
        b = find_set(b);
        if (a != b) {
            // Подвешиваем меньшее к большему
            if (size[a] < size[b])
                swap(a, b);
            parent[b] = a;
            size[a] += size[b];
        }
    }
};

int main() {
    int n = 5;
    DSU dsu(n + 1);
    dsu.union_sets(1, 2);
    dsu.union_sets(3, 4);
    
    // Проверка, в одном ли они множестве
    if (dsu.find_set(1) == dsu.find_set(2)) {
        cout << "1 and 2 are connected\n";
    }
    return 0;
}
```

### ✨ Ключевые моменты
- В дереве N вершин и N - 1 ребро. В нем нет циклов.
- При DFS по дереву просто проверяйте `if (v != parent)` вместо массива visited.
- DSU (СНМ) идеально подходит для поиска компонент связности и проверки графа на связность онлайн.
- Всегда используйте сжатие путей в DSU `parent[v] = find_set(parent[v])`.

## 💎 Тема 11: Продвинутое ДП
### 🎯 Цель
Изучить техники ДП по маскам и на отрезках.

### 📖 Теория
**Уровни мастера: ДП по подмножествам и интервалам**

Когда вы освоите базовое динамическое программирование (линейное и двумерное), перед вами откроются новые, более сложные, но невероятно мощные виды ДП.

**ДП по маскам (Bitmask DP)**. Что делать, если состояние задачи — это не просто одно число (позиция), а целое множество выбранных элементов? Если элементов немного (обычно N <= 20), множество можно представить в виде двоичного числа — битовой маски. Единица в i-м бите означает, что i-й элемент включен во множество, нуль — не включен. 
Например, маска `101 (в двоичной) = 5 (в десятичной)` означает, что выбраны 0-й и 2-й элементы. Битовые операции (`&`, `|`, `^`, `<<`) позволяют быстро работать с такими множествами.

**ДП на отрезках (Interval DP)**. Иногда, чтобы решить задачу для отрезка `[L, R]`, нам нужно разбить его на два меньших отрезка: `[L, k]` и `[k+1, R]`. В этом случае состояние ДП — это левая и правая границы (иногда с доп. параметрами). Обход обычно делается так: внешний цикл перебирает длину отрезка от 1 до N, средний цикл — левую границу, а внутренний — точку разреза.

**Наибольшая возрастающая подпоследовательность (LIS)**. Задача: найти самую длинную подпоследовательность в массиве, которая строго возрастает. Базовое ДП решает ее за O(N^2), но с помощью бинарного поиска (или дерева отрезков) можно улучшить время до O(N log N).

**Задача о рюкзаке (Knapsack)**. Классическая задача: есть рюкзак вместимости W и предметы с весом и стоимостью. Нужно набрать максимальную стоимость. Состояние — `dp[i][w]` (максимальная стоимость, если рассмотрели i предметов, и общий вес равен w).

### 💻 Шаблон кода
```cpp
#include <bits/stdc++.h>
using namespace std;

// Пример: ДП по битовым маскам. Задача коммивояжера (TSP).
const int INF = 1e9;
int n = 4;
int dist[20][20]; // Матрица расстояний
int dp[1 << 20][20]; // dp[mask][u] - мин. путь через вершины в маске, заканчивающийся в u

int solve() {
    // Инициализация бесконечностью
    for (int i = 0; i < (1 << n); i++) {
        for (int j = 0; j < n; j++) {
            dp[i][j] = INF;
        }
    }
    
    // Базовый случай: старт из вершины 0
    dp[1][0] = 0; // Маска 1 (0001) - посещена только вершина 0
    
    // Перебор всех масок
    for (int mask = 1; mask < (1 << n); mask++) {
        for (int u = 0; u < n; u++) {
            // Если вершина u есть в маске
            if (mask & (1 << u)) {
                for (int v = 0; v < n; v++) {
                    // Если вершины v еще нет в маске
                    if (!(mask & (1 << v))) {
                        int next_mask = mask | (1 << v);
                        dp[next_mask][v] = min(dp[next_mask][v], dp[mask][u] + dist[u][v]);
                    }
                }
            }
        }
    }
    
    // Ищем минимальный путь через все вершины
    int ans = INF;
    for (int i = 1; i < n; i++) {
        // Возвращаемся в стартовую (0)
        ans = min(ans, dp[(1 << n) - 1][i] + dist[i][0]);
    }
    return ans;
}
```

### ✨ Ключевые моменты
- Битовая маска — это просто число, где каждый бит означает наличие (1) или отсутствие (0) элемента.
- В ДП на отрезках итерируйтесь по длине отрезка (от 1 до N), а не по левой и правой границам в произвольном порядке.
- Для LIS за O(N log N) используйте std::lower_bound и массив наименьших последних элементов.

## 🔤 Тема 12: Строковые алгоритмы
### 🎯 Цель
Изучить хеширование строк, префикс-функцию и Z-функцию.

### 📖 Теория
**Укрощение строк: Хеши, Префиксы и Z-функция**

Работа со строками — огромный раздел алгоритмов. Нам часто нужно находить подстроки, искать закономерности или проверять равенство длинных строк. Обычное посимвольное сравнение работает медленно (за O(N)).

**Полиномиальное хеширование (String Hashing)** — это способ превратить любую строку в одно большое число (хэш). Если хэши двух строк равны, то, скорее всего, равны и сами строки (вероятность коллизии очень мала, особенно если использовать двойное хеширование). Прелесть в том, что зная хэш всей строки и ее префиксов, мы можем за O(1) вычислить хэш ЛЮБОЙ подстроки, используя формулу, похожую на префиксные суммы. Это позволяет сравнивать подстроки за константное время!

**Префикс-функция (Алгоритм КМП - Кнута-Морриса-Пратта)**. Для каждого символа строки вычисляется длина наибольшего префикса строки, который совпадает с ее суффиксом, заканчивающимся в этой позиции (при этом префикс не должен совпадать со всей строкой). Массив этих длин (`pi`) позволяет быстро находить вхождения паттерна в текст. Мы просто считаем префикс-функцию для строки `паттерн + # + текст`.

**Z-функция**. Очень похожа на префикс-функцию, но немного другая постановка. Массив `Z[i]` хранит наибольшую длину префикса строки, который совпадает с подстрокой, начинающейся с позиции `i`. Она также вычисляется за линейное время O(N) и решает те же задачи (например, поиск подстроки в строке), но иногда Z-функцию интуитивно проще использовать.

Выбор между хешами и Z/префикс-функцией зависит от задачи. Хеши универсальнее и проще пишутся, но могут не пройти тесты из-за коллизий (особенно если против вас используют специальные тесты-убийцы, так называемый anti-hash тест). Z и префикс-функция абсолютно точны и работают строго за O(N).

### 💻 Шаблон кода
```cpp
#include <bits/stdc++.h>
using namespace std;

// Z-функция за O(N)
vector<int> z_function(string s) {
    int n = s.length();
    vector<int> z(n);
    for (int i = 1, l = 0, r = 0; i < n; ++i) {
        if (i <= r)
            z[i] = min(r - i + 1, z[i - l]);
        while (i + z[i] < n && s[z[i]] == s[i + z[i]])
            ++z[i];
        if (i + z[i] - 1 > r)
            l = i, r = i + z[i] - 1;
    }
    return z;
}

// Префикс-функция за O(N)
vector<int> prefix_function(string s) {
    int n = s.length();
    vector<int> pi(n);
    for (int i = 1; i < n; i++) {
        int j = pi[i-1];
        while (j > 0 && s[i] != s[j])
            j = pi[j-1];
        if (s[i] == s[j])
            j++;
        pi[i] = j;
    }
    return pi;
}

int main() {
    string text = "abacaba";
    string pattern = "aba";
    
    // Ищем pattern в text с помощью Z-функции
    string s = pattern + "#" + text;
    vector<int> z = z_function(s);
    
    cout << "Found at indices: ";
    for (int i = pattern.length() + 1; i < s.length(); i++) {
        if (z[i] == pattern.length()) {
            // Индекс в оригинальном тексте
            cout << i - pattern.length() - 1 << " ";
        }
    }
    cout << "\n";
    return 0;
}
```

### ✨ Ключевые моменты
- Хеширование сводит сравнение подстрок к O(1) после прекалька за O(N).
- КМП (Префикс-функция) находит длины совпадающих суффиксов и префиксов.
- Z-функция находит совпадающие префиксы строки с ее серединой.
- Для поиска `P` в `T` склейте их: `P + '#' + T` и запустите Z или префикс-функцию.
